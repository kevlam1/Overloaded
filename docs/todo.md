- [ ] **Still open:** a table whose host never comes back and never makes a new one stays in the database forever, because nothing runs on a timer (rules only refuse writes to an expired table). The main cost is privacy, not space: names and game zones are kept, against "lobbies are deleted when inactive". Space is a small risk (my unmeasured guess: tens of KB per table, so 20,000 or more tables for 1 GB); the real risk is a script making thousands of anonymous accounts that each create a table. Why it can't just clear itself: the rules only answer yes or no to a request, so something has to send the delete. Cloud Functions could run a scheduled cleanup, but Firebase's docs (read 2026-10-27) say deploying them needs the Blaze (pay as you go) plan, so they are out under the no-paid-service rule. Options: (A) any signed-in member of an expired table may delete it, so whoever opens it cleans it up, and (B) a host's new table deletes their old one (decided); neither catches a table nobody ever opens again. (C) A free scheduled job outside Firebase would be the only way to guarantee it. Checked 2026-10-27: Vercel Cron on the Hobby plan runs at most once a day, with timing only within the hour (±59 minutes), and runs a Vercel Function; GitHub Actions has a `schedule` trigger (its free limits were not read); Supabase Cron is `pg_cron` (free-plan availability not checked). A job using Firebase's admin access bypasses the rules, so it can list every table. It needs the `firebase-admin` library (license not checked, ask first) and an admin key kept as a Vercel environment variable, never in the repo. Industry practice is a mix: expiry in the data store where it exists (Redis `EXPIRE`, DynamoDB TTL, Firestore TTL policies; Realtime Database has none I found), a scheduled job, delete-on-access, and an explicit end-of-session delete. A size limit on zones when their shapes are designed bounds abuse. **Kevin chose A and C on 2026-10-27.** A is a small rules change (next). C needs a plan shown to Kevin first: which free host, its limits and cost, and where the admin key lives (never in the repo).
